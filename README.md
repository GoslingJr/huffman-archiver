# huffman-archiver

[![CI](https://github.com/GoslingJr/huffman-archiver/actions/workflows/ci.yml/badge.svg)](https://github.com/GoslingJr/huffman-archiver/actions/workflows/ci.yml)
[![CodeQL](https://github.com/GoslingJr/huffman-archiver/actions/workflows/codeql.yml/badge.svg)](https://github.com/GoslingJr/huffman-archiver/actions/workflows/codeql.yml)
[![License: MIT](https://img.shields.io/github/license/GoslingJr/huffman-archiver)](LICENSE)

Консольный архиватор файлов на C++17, реализующий классический алгоритм сжатия Хаффмана: строит дерево по частотам байтов во входном файле, кодирует данные префиксными кодами переменной длины и упаковывает их побитово. Учебный проект (курсовая практика).

## Пример использования

```sh
# собрать (см. раздел "Сборка" ниже), затем:
./huffman -c input.txt input.huf     # сжать файл
./huffman -d input.huf output.txt    # разжать обратно
diff input.txt output.txt            # убедиться, что содержимое совпадает
```

На связном тексте степень сжатия обычно в районе 1.5–2x, на данных с маленьким алфавитом — заметно выше (подробные замеры — в [`benchmarks/README.md`](benchmarks/README.md)). На равномерно случайных данных сжатия практически нет — это ожидаемое поведение алгоритма Хаффмана, а не баг.

> На Windows перед запуском в PowerShell/cmd, если нужно увидеть кириллицу в выводе (сообщения об успехе/ошибках), один раз выполните `chcp 65001`, чтобы переключить консоль на UTF-8.

## Сборка

Нужен компилятор с поддержкой C++17 (проверено на GCC ≥ 11; на Windows — через [MSYS2](https://www.msys2.org/), пакет `mingw-w64-x86_64-gcc`).

### Через CMake (рекомендуется)

```sh
cmake -B build
cmake --build build
```

Исполняемый файл появится в `build/huffman` (`build/huffman.exe` на Windows).

Собрать с санитайзерами (AddressSanitizer + UndefinedBehaviorSanitizer) для отладки:

```sh
cmake -B build-san -DHUFFMAN_ENABLE_SANITIZERS=ON
cmake --build build-san
```

### Через Makefile (Linux/MinGW)

```sh
make all      # соберёт build/huffman
make test     # соберёт и прогонит тесты
```

На Windows команда обычно называется `mingw32-make`, если используется MinGW/MSYS2. Если ни `make`, ни `cmake` не установлены — их можно поставить через MSYS2: `pacman -S mingw-w64-x86_64-cmake mingw-w64-x86_64-make`.

## Формат сжатого файла (`.huf`)

```
[8 байт]  originalSize   — размер исходного файла в байтах
[2 байта] uniqueCount    — количество уникальных символов (0, если файл пуст)
uniqueCount раз повторяется:
  [1 байт]  символ
  [8 байт]  его частота в исходном файле
далее — сами данные, закодированные префиксными кодами Хаффмана,
упакованные по 8 бит в байт (последний байт может быть дополнен нулями).
```

Подробнее — в комментариях [`include/archiver.h`](include/archiver.h).

## Архитектура

Проект разбит на независимые модули (в `include/` и `src/`):

| Модуль | Отвечает за |
| --- | --- |
| `bit_io` (`BitWriter`/`BitReader`) | побитовую запись/чтение файла: накопление битов в байтовый буфер и обратно |
| `huffman_tree` (`HuffmanTree`) | построение дерева Хаффмана по таблице частот (min-heap), генерацию таблицы префиксных кодов и декодирование символов из битового потока; внутреннее устройство узла дерева скрыто от остального кода |
| `archiver` (`Archiver`) | формат `.huf`-файла целиком: собирает таблицу частот, пишет/читает заголовок, вызывает `HuffmanTree` и `BitWriter`/`BitReader` для кодирования и декодирования данных |
| `main` | тонкий CLI (`-c`/`-d`), единственное место в проекте, где происходит консольный ввод-вывод |

Ошибки (не открылся файл, повреждённые/обрезанные сжатые данные и т.п.) сообщаются исключениями (`std::runtime_error`) из `Archiver`, а не кодами возврата — `main` их перехватывает и печатает пользователю.

## Тестирование

Три независимых набора тестов на собственном минималистичном фреймворке без внешних зависимостей (`tests/test_utils.h`):

- `test_bit_io` — побитовая запись/чтение;
- `test_huffman_tree` — построение дерева, префиксность кодов, детерминированность;
- `test_archiver` — сквозной цикл сжатие → разжатие на разных данных (текст, бинарные данные, пустой файл, файл с одним уникальным символом), а также проверка, что ошибки (нет входного файла, обрезанные сжатые данные) корректно выбрасывают исключения.

Все три набора запускаются в CI (см. бейдж выше) в обычной сборке и отдельно — под AddressSanitizer/UndefinedBehaviorSanitizer. Форматирование кода проверяется `clang-format` (конфигурация — [`.clang-format`](.clang-format)) тоже в CI.

Замеры производительности и степени сжатия — в [`benchmarks/`](benchmarks/README.md).
