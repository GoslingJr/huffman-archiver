# Эксперименты: степень сжатия и скорость работы

## Как запустить

```
cd ../             # в корень проекта
make all            # собрать huffman (если ещё не собран)
cd benchmarks
python3 generate_data.py   # сгенерировать тестовые файлы
python3 run_benchmark.py   # прогнать замеры и построить графики
```

Требуются `python3` с `matplotlib` (`pip install matplotlib`, если его нет).

## Что измеряется

Для каждого файла:
- **степень сжатия** = размер исходного файла / размер сжатого;
- **время сжатия** и **время разжатия** — среднее и среднеквадратичное
  отклонение по 5 повторным прогонам (константа `REPEATS` в `run_benchmark.py`);
- после каждого разжатия скрипт сверяет разжатый файл с исходным побайтово
  (доп. проверка корректности поверх модульных тестов).

## Типы тестовых данных

- **text** — связный текст с неравномерным распределением "слов" (имитация
  естественного языка) — Хаффман должен давать заметное сжатие;
- **random** — равномерно случайные байты — теоретически близкий к
  наихудшему случаю для Хаффмана (энтропия максимальна, сжатие минимально
  или отсутствует, а на маленьких файлах результат может быть даже больше
  исходного из-за накладных расходов на хранение таблицы частот);
- **repetitive** — данные с малым алфавитом (3 уникальных символа) —
  ожидаемо самое сильное сжатие.

Размеры: 1 КБ, 10 КБ, 100 КБ, 1 МБ, 5 МБ — на каждый тип данных.

## Результаты одного прогона (пример)

См. `results.csv` — там точные числа. На нашем прогоне:

| Тип        | Степень сжатия (1 МБ) | Комментарий |
|------------|------------------------|-------------|
| repetitive | ~4.80x                 | мало уникальных символов — короткие коды |
| text       | ~1.87x                 | типичный результат для текста |
| random     | ~1.00x                 | равномерное распределение — Хаффман бессилен |

На маленьком файле (1 КБ) случайных данных степень сжатия была < 1 (файл
увеличился) — это ожидаемо и объясняется тем, что накладные расходы на
хранение таблицы частот (в нашем формате — до 256×9 байт) сравнимы с
размером самого файла.

Графики:
- `compression_ratio.png` — степень сжатия от размера файла (для трёх типов данных);
- `compress_speed.png` — время сжатия от размера файла (лог-лог, с error bar'ами);
- `decompress_speed.png` — время разжатия от размера файла (аналогично).

Разжатие в целом медленнее сжатия — это объясняется тем, что при разжатии
приходится обходить дерево по одному биту за символ, а при сжатии код
известен целиком и пишется напрямую.
